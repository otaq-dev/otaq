# Design update S: the epic lead (2026-10-16)

Decision **0083** gives each epic a **lead**: one read-only agent session that plans the epic with the user, answers its
children's questions first, sends one note to a stuck child, and re-plans after each child merges. Children stay
ordinary tickets with their own cards, worktrees and terminals. Apply after update R. Update the existing design; don't
start over. Affected briefs: 03 (board and strip), 04 (cards), 05 (epic panel), 10 (inbox), 16 (recovery).

**Attach to every prompt** (the design agent has no repository access): `design-briefs/00-README.md`,
`01-design-system.md`, this file, `decisions/0083-epic-lead-agent.md`, `0080-epic-tracks-on-the-board.md`,
`0068-project-agent.md`, and briefs `03`, `04`, `05`, `10`, `16`. Optional, for prompts 2 and 3:
`decisions/0059-epics-as-delivery-units.md` (the epic in Review) and `0061-answer-options-for-human-questions.md` (the
recommended option).

Run the prompts below **in order, one per design-agent session** (or one after the other in the same session), and
check each result before pasting the next. Prompt 1 builds the parts, prompt 2 the board flows, prompt 3 the epic panel,
inbox and restart, prompt 4 is the agent's own check. Every prompt starts with the shared preamble.

## Audit (2026-10-16)
Checked against 0083 (text of every light row, dark rows compared with light, screenshots of frames 23 and 26). The
design follows the decision, including the points that are easy to get wrong:
- A child waiting for its lead is calm ("Asked lead", rank 7), never turquoise; a passed-on question is turquoise "via
  Wishlist lead"; the inbox count only moves when something reaches the user (21–22 unchanged, 23 11 → 12).
- The lead's own question turns the track label turquoise and no child (26).
- The stuck child gets one note with the round counter back at 0 (24); the second time it reaches the user with the note
  and the lead's view, and the final actions stay the user's (25, inbox).
- Only merges and questions wake the lead; the Lead tab shows only `otaq` commands, never edits, moves or merges.
- The lead ends at Ready for Review; Open PR runs in its own delivery session (27, Lead tab · ended).
- After a restart: "ended by restart · Resume", children ask the user directly, not in Resume all (16).
- Not under "Terminals & agents". No new colours. Dark rows carry the same content as light.
- Frame 17 uses SHOP-45 **Search** (PAY-130, 2 children), as the 0080 states draw it; the prompt's "Wishlist analytics"
  was wrong and is corrected above.

```text
changed frame comes in light and dark. Put new work in new rows marked "(0083)" under an "Update S · header (0083)" row

Read first, in the files attached to this message:
  1. design-briefs/00-README.md (product, vocabulary, sample data)
  2. design-briefs/01-design-system.md
  3. decisions/0083-epic-lead-agent.md: the source of truth. Then 0080 (the strip, tracks, sleeves) and 0068 (Project
     agents, whose look the lead reuses)
  4. design-briefs/CHANGES-2026-10-16-s.md, "Sample data for update S": use exactly these keys, names and texts
  5. the "Update S (0083)" section at the end of briefs 03, 04, 05 and 10

What changed, in one paragraph: an epic now has a "lead", a read-only agent that directs it. The user opens it from the
epic card (also in Backlog) to plan; dragging an epic without a lead starts one. Otaq wakes it after each child merges,
when a child asks a question, and once when a child gets stuck. It answers what it can, passes the rest to the user,
edits the children that haven't started and adds new ones. It never edits code, moves cards, merges or answers
permission prompts. It lives on its epic: a status on the epic card and at the start of the track, and a terminal in
the epic panel. It is NOT listed under "Terminals & agents".

Rules that hold in every frame:
  - Violet = epic / agent-made (as in 0080 and 0068); turquoise = needs the user (0077). Don't add new colours.
  - A child waiting for its lead is NOT turquoise; it only turns turquoise when the lead passes something to the user.
  - The lead is never drawn editing files, moving a card or merging.
If something in a decision seems to conflict with the existing design, follow the decision and list the conflict in a
"Notes & open questions (0083)" row instead of guessing.
```
