## 1. Ticket keys: `#18` → `SHOP-18` (decision 0029)
Every ticket is now identified as **project key + number**, unique across projects.
- `shop-web` → key **SHOP**, `billing-api` → key **BILL**, `crewboard` → key **CREW**.
- Replace **every** `#NN` ticket reference: frame titles (for example "Panel — #22 Needs you" → "Panel — SHOP-22
  Needs you"), cards, Stack lists, dependency badges (`⛓ SHOP-18 SHOP-19`), "waiting on SHOP-20",
  "Parent SHOP-18 changed", inbox items, toasts, terminal text and the Runs list.
- billing-api tickets `#4` / `#5` → **BILL-4** / **BILL-5**.
- **Branch names:** `crewboard/SHOP-18-checkout-api`.
- **Attach command** in the terminal header: `crewboard attach SHOP-18`.
- **Not changed:** PR numbers stay as they are (`PR #481`).
- **Project switcher:** show each project's key next to its name (`shop-web · SHOP`).
- **Add project** (onboarding, brief 14, and the project-switcher flow): add a **Project key** field, prefilled from
  the repo name (for example `SHOP`) and editable. Hint text: "Used in ticket IDs like SHOP-18. Can't be changed later."
- **Per-project settings** (brief 15): show the key **read-only**.

## 2. Agents can ask each other questions (decision 0030)
An agent can ask the agent of a **directly linked** ticket (parent or child) a question **through Crewboard**.
Everything is logged and visible.
- **New card state** (brief 04): "asked SHOP-18 · waiting for answer". Sample: SHOP-20.
- **New Messages section in the side panel** (brief 05): a thread of questions and answers between linked tickets.
  Sample: SHOP-20 → SHOP-18: "What does POST /checkout return on a declined card?" → answered. Show the states
  asked, delivered (when the target agent was idle), answered, and "sent to your inbox: SHOP-17 has no live
  session".
- **New inbox item type** (brief 10), in the first group: "SHOP-21 asks SHOP-17 (Done): which Stripe API
  version?", with the actions **Answer** and **Resume SHOP-17**.

## 3. Command names in any UI copy (decisions 0031 and 0032)
There is no MCP server anymore. Agents use the `crewboard` CLI (beads-style). Wherever the designs show tool or
command names (terminal mocks, tooltips, Runs history, empty-state hints):
| Old | New |
|---|---|
| `ask_human` | `crewboard ask human` |
| `ready_for_review` | `crewboard review submit` |
| `get_ticket` | `crewboard prime` / `crewboard show` |
| `get_review_feedback` | `crewboard review feedback` |
| `create_ticket` / `link_tickets` | `crewboard create` / `crewboard dep add` |
| `post_investigation` | `crewboard investigation post` |
| `ask_ticket` / `answer_question` | `crewboard ask SHOP-18` / `crewboard answer <id>` |

- **Planning terminal** (brief 17): example output can show `crewboard create -f plan.md` creating SHOP-18 to SHOP-21.
