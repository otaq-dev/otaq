## Remove the Needs Input column (decision 0037)
The board is now **5 columns: Backlog → Dev (Queued + Agent Working) → Ready for Review → Approved → Done**.
- **Delete the Needs Input column** from every board (light and dark, every width, the app shell, board & columns,
  inbox context, recovery, onboarding and storyboards).
- **Tickets where the agent asks a question** (SHOP-23, SHOP-12: "Asks you") or waits on a permission prompt
  (SHOP-22: "Needs you") **stay in Dev → Agent Working**. They keep their **orange highlight** (as designed today) and are
  **sorted to the top** of the Agent Working section, in inbox order.
- Update the drag rules, column lists, status legend and keyboard map. Replace any copy that says "moves to Needs Input"
  with "shows *Asks you* at the top of Dev".
- With fewer columns, use the space: at 1440 px all 5 columns can be open (Done may still collapse).
- The **Needs-you inbox is unchanged.**

## Epics (decision 0039)
Beads-style epics: a big piece of work split into tickets.
- **An epic lives only in Backlog.** It is a container with no agent, branch or worktree, and it can't be dragged to Dev
  (show the "not allowed" drop feedback). Design an **epic card** for Backlog showing title, key, progress ("1 / 3 done")
  and a compact list of its child tickets with their statuses. It can expand and collapse.
- **Sample:** **SHOP-40 Wishlist** (epic) with children:
  - **SHOP-40.1** Wishlist API: Done · Merged
  - **SHOP-40.2** Wishlist button: Dev · Agent Working, depends on SHOP-40.1
  - **SHOP-40.3** Wishlist page: Backlog
- **Hierarchical keys:** children are **SHOP-40.1, SHOP-40.2, …** (one level only). Their branches and worktrees use the
  full key (`crewboard/SHOP-40.2-wishlist-button`, `~/.crewboard/wt/shop-web/SHOP-40.2`).
- **Child cards** are normal cards plus a small **epic chip** ("Wishlist"). Add a board **filter by epic**.
- **Epic panel** (clicking an epic): description, progress, the child list (click to jump), and **Add ticket to epic**.
  It has no Terminal, Diff, Run or Shell tabs.
- **Planning terminal (17):** a sample where Claude runs `crewboard create --parent SHOP-40 "Wishlist page"` and the
  child appears under the epic in real time.
- **Ticket editor (08):** a "Type: Ticket / Epic" choice when creating, and an "Epic" field (read-only once created,
  because the key is fixed).
- **Completion:** when all children are Done, the epic **moves to Done automatically** with a quiet toast
  ("Epic SHOP-40 Wishlist done"). Show the epic card inside Done.
