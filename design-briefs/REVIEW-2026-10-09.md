# Design review of the first Pencil pass (2026-10-09)

Reviewed: the Pencil file (23 frames). Looked at closely: board, panel + terminal, card variants, inbox, stack
storyboards, diff and review, side panel. Also checked all text in the file against the decision log.

**Overall: strong work.** The pass covers every brief and follows the principles well:
- Clear rules for which flag wins a card's main status pill
- No silent approve when dropping a card on Approved
- "Crewboard doesn't watch this PR" spelled out in the UI
- Calm empty and "all clear" states
- Toasts don't pile up
- The usage-limit banner replaces per-agent alerts

The items below are what's left.

## A. Conflicts with decisions (the user decides; see the decision log once settled)
1. ✅ **Decided: keep the design (no auto-advance).** 0016 has been updated. **The inbox doesn't jump to the next item on its own.** The design waits for ⌘J after you answer.
   Decision 0016 says "once the item is handled, the next one opens". The designer's reasoning is that the user
   decides when to move on.
2. ✅ **Decided (0033): Mark closed closes the ticket.** It goes to Done labeled "Closed · not merged" and can be reopened by dragging it out. Any ticket can also be closed with "Close ticket". See section C. Originally: **Mark closed sends the ticket back to Ready for Review.** Decision 0017 says "Mark closed: the factory does
   nothing else. The user decides where the ticket goes."
3. ✅ **Decided (0015 refined): keep the design.** An open PR on the parent unblocks the child (the child can Open PR
   targeting the parent's branch). A child's Local merge still needs the parent merged. Originally: **Opening a PR counts as approving the parent, so its child can be approved (stacked PRs).** Decision 0015 says
   approval goes "bottom-up, so a child cannot be approved before its parent". The design reads this as: a child
   can open its PR once the parent's PR is open, but a Local merge still needs the parent to be merged.

## B. UX fixes (no decision needed; for the designer after the current update pass)
1. **Esc inside the terminal.** Claude Code itself uses **Esc** (interrupt the agent, cancel a prompt option) and
   **Esc Esc** (rewind). The current design uses Esc to leave the terminal and sends Esc to the CLI only on a
   double press, which breaks both. Fix: while the terminal has focus, **every key goes to the CLI, Esc
   included**. Leave the terminal with a dedicated shortcut (for example ⌘⇧` / Ctrl+Shift+`), a click outside, or
   the inbox shortcut.
2. **Shortcuts on Windows and Linux while the terminal has focus.** ⌘ becomes Ctrl there, and Ctrl+letter belongs to
   the terminal (Ctrl+J, Ctrl+T, Ctrl+C…). App shortcuts must use **Ctrl+Shift+…** on Windows and Linux while the
   terminal is focused, the way VS Code and Windows Terminal do. Show both forms in the keyboard map.
3. **"Working" counts don't agree.** The header says "3 agents working", the Dev section says "AGENT WORKING 4",
   and the all-clear screen says "5 agents are working". Define "running" as "an agent is actively doing a turn",
   label the header chip "3 running (all projects)", and keep section headers as card counts.
4. **Approved card:** the button "Closed" should read **"Mark closed"**. It is an action, not a state.
5. ~~Changes Requested card~~: replaced by C3 (the column is removed).
6. **Board sample:** SHOP-20 shows *Paused · Parent SHOP-18 changed* while SHOP-18 sits in Ready for Review.
   That can't happen: children resume when the parent is back in Review. Show SHOP-20 as **Restacking onto SHOP-18**
   on the board. The sample data in `00-README.md` has been corrected. This was an error in the brief.
7. **Resume all** in the inbox's Interrupted group also lists SHOP-28 (start interrupted). Make clear that Resume all
   resumes interrupted sessions only, and that a start-interrupted ticket needs its own **Retry start**.
8. **Project rail:** use project keys (SHOP, BILL, CREW) instead of the generated initials (SW, BA, CB).
9. **Leftover old names** (the current update pass should catch these): `ask_human` in the inbox and terminal mocks,
   and `crewboard.ready_for_review(summary)` in a terminal mock.

## C. Design changes from decisions made in this review
1. **Inbox (0016):** keep the current design. There is no auto-advance, and ⌘J moves to the next item. No change needed.
2. **Closed tickets (0033):**
   - The Done column shows two kinds of finished tickets: **"Merged"** and **"Closed · not merged"**.
   - **Mark closed** (SHOP-26) moves the ticket there. Update the confirmation copy in the "05 · Ticket side
     panel → SHOP-26 · Approved, PR open" frame. It should no longer say "moves the ticket back to Ready for Review".
   - A **Close ticket** action on every ticket, for example in the panel's "…" menu and the card's right-click menu,
     with a confirmation that mentions stopping a running agent.
   - **Reopen:** drag out of Done, or use a "Reopen" button on closed tickets. Allowed targets are Backlog,
     Investigate and Ready for Dev.
   - **Children of a closed parent:** a new card flag, "parent SHOP-26 closed", and a new inbox item (group 2) with
     the actions **Reopen parent** and **Remove dependency**.
3. **No Changes Requested column (0034):**
   - Remove the column from the board (light and dark, every width).
   - **Send back** is an action (Diff tab and panel action bar). The ticket moves straight back to **Dev → Agent
     Working**, or Queued if the optional limit is full.
   - New card marker, **"Sent back · 3 comments · round 2"** (SHOP-27 in the sample).
   - Update the stack storyboard step 3 ("Parent sent back"): SHOP-18 shows in Dev with the Sent back marker instead
     of a Changes Requested column. Its children still pause.
   - Update the Send-back confirmation copy: it no longer mentions "moves to Changes Requested".
