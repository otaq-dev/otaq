## 1. Pinned tickets (0047)
- **Pin / Unpin** in the card's right-click menu and the panel's "…" menu. Pinned cards show a small **pin icon**.
- A pinned ticket is **always first in its column**, above orange "Asks you / Needs you / Idle" cards. The pin
  **follows the ticket** across columns. With several pins, the most recently pinned is first.
- **Sample:** pin **SHOP-19** (Dev → Agent Working). It sits above SHOP-22 and SHOP-23.
- Add the "Pinned" variant to the card-variants page.

## 2. Orange family: Asks you / Needs you / Idle (0042)
- Add **"Idle"** as a third orange label for agents that ended their turn without submitting or asking. Sample: SHOP-19
  variant, "Idle · ended its turn: 'Should I also update the tests?'"
- All three sort to the top of Dev (below pinned cards) and appear in **inbox group 1**.
- The highlight **clears on the user's input**: Enter in the ticket's terminal, an answer from the inbox, or the agent running
  a `crewboard` command again. Show the before and after of SHOP-23 once it's answered.

## 3. "Waiting for limit reset" (0046)
- While the usage-limit banner is showing, stopped agents show **"Waiting for limit reset"** (neutral, not orange) and
  **don't create inbox items**. Update the usage-limit storyboard in frame 11 and the inbox "usage limit active" state.

## 4. Local merge when main moved (0038)
- A **"conflicts with main"** flag on Review cards and in the panel header (a read-only check after every merge).
- Local merge states:
  - "Rebasing onto main…" → success
  - a conflict, with the button **"Send to agent to fix"** (returns the ticket to Dev)
  - a refusal: "shop-web has uncommitted changes on main. Clean up and retry." (Crewboard never stashes)

## 5. Changed since review (0043)
- When new commits appeared after a ticket entered Review, Approve shows **"SHOP-18 changed since you reviewed it · 1
  new commit"**, with a diff of **only the new commits** and the actions **Approve anyway** and **Send back**.

## 6. PR rework (0041)
- **No Send back on Approved.** To rework a PR ticket, **drag it from Approved back to Ready for Review**. The PR chip stays,
  then the user uses Send back. Show this drag as allowed.
- After rework, Approve for a ticket with an open PR shows **"Push to PR #481"**, which returns it to Approved · PR open.
  The agent never pushes.
- Stacked children with open PRs, after a restack, show **"PR out of date · Push"** (always a click).

## 7. Closing and reopening (0044)
- **Closed parent:** working children pause with "parent SHOP-18 closed", and an inbox item offers Reopen parent and Remove dependency.
- **Close epic** with unfinished tickets: one confirmation listing the tickets to close and the agents to stop. Merged tickets stay.
- An **epic with nothing merged** shows "Closed · not merged" in Done.
- **Move to epic:** a ticket that has never been to Dev gets a "Move to epic…" action. Its key changes (SHOP-51 → SHOP-50.2),
  and a note says the old key still works.
- **Reopen** only appears on **Closed** tickets. Merged tickets have no Reopen and can't be dragged out of Done.

## 8. Depending on an epic (0046)
- The Depends-on picker in the ticket editor also lists **epics**. A dependency on an epic shows "waiting on epic SHOP-40 (2 / 3
  done)". It's ready when the epic is Done with at least one merged ticket.

## 9. After a reboot (0045)
- Only **Dev** tickets become Interrupted. Review and Approved tickets (SHOP-18, SHOP-26) stay as they are and are
  **not in Resume all**.
- An orange ticket keeps its question after a reboot. Answering SHOP-23 from the inbox resumes it and delivers the
  answer in one click.
- Run and Shell show **"stopped by restart"**.
- **"Before the restart" view** in an Interrupted ticket's Terminal tab: the agent's last messages and actions (read from
  Claude's saved conversation), plus a "conversation no longer available" variant.
- **History tab** lists the ticket's Claude session IDs.

## 10. Agent instructions (0040)
- **Settings → global:** an "Agent instructions" text field, for example "Ask before coding. Run tests before submitting."
- **Settings → project:** a per-project override, for example "Use my /tdd skill. Run `pnpm test` before submitting. Never touch
  migrations." Empty means the global default is used.
- Optionally, a small "Instructions: shop-web" line in the agent terminal's header strip, linking to settings.
