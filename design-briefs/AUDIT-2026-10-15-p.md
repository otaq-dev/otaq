# Design audit: update P, the rich Markdown editor (2026-10-15)

Scope: the update P rows in `crewboard.pen`. In "08 · Ticket editor" these are the parts, edit mode a/b (light and dark),
d–g, h–j, 6–7 and Open questions. In "05 · Ticket side panel" they are the read-mode row c (light, Copied, dark).

Methods:
- A text dump of every update P frame, checked against each item of the prompt in `CHANGES-2026-10-15-p.md`
- A clipping scan of every text node in those frames
- PNG exports of all 17 sheets, checked by eye
- The shortcuts checked against `decisions/0058`
- The licenses of the packages the design implies, checked on npm

## Result: update P is applied in full
- **Every requested state is present:** a–j, 6 and 7. That includes "Copy as Markdown" with its Copied state, the "Markdown"
  source toggle, the link popover and bubble, the table bar, the code-block language picker, overflow at 480 px, max height
  with a pinned toolbar, and the Rendered / Markdown compare.
- **The example description is complete** in the toolbar, read mode, source mode and the clipboard sample, including the
  headings, bold, link, italic, task list, inline code, table and `ts` code block.
- **The hint, placeholder and footers** match the prompt: "Markdown · paste keeps formatting" and "Context, constraints,
  links…".
- **No text is clipped** anywhere in the update P frames.
- **Out of scope is respected:** no colours, sizes, underline, images, slash menu or bubble menu are offered.
- **The designer listed 10 open questions** instead of deciding them silently. They're under "Decisions needed" below.

## Findings (design fixes, no decision needed)
1. **j · Editing while the agent works mixes two states.** The "Saved. SHOP-19's agent will be told…" banner sits above an
   editor that is still open, with the toolbar, the caret and no Save / Cancel row. Brief 08 has two moments: while
   editing, the note sits under the Save button; after saving, the banner shows over read mode. Draw both: (a) editing,
   with the toolbar, Save / Cancel and the note under Save; (b) after Save, with the banner and the rendered description in
   read mode.
2. **h · Narrow Ticket tab: the code block is cut off** ("…autocomplete(query, { co") with no sign that it continues. Long
   code lines should scroll sideways inside the block, without wrapping. Show a right-edge fade and the thin horizontal
   scrollbar on hover, and annotate it.
3. **The Copy-as-Markdown tooltip still holds a hidden "⇧⌘C" key chip** (node `M8IwH`, in a disabled "k" frame, read mode
   light). ⇧⌘C was removed in update J and no shortcut is proposed. Delete the hidden node so nobody turns it back on.
4. **The read-mode annotations contradict the open questions.** Annotations (`EqOPp`) say "Copy as Markdown" also sits in
   the Ticket tab's header when Edit isn't shown. Open questions say it is drawn only next to Edit. Keep one wording until
   decision D7 is made.
5. **The example key clashes:** SHOP-26 is already "Add sitemap" (Approved, PR open) in brief 05. This was the prompt's
   mistake. Rename the update P ticket to **SHOP-47** (unused) everywhere in the update P rows: the title, the branch
   `otaq/SHOP-47`, "nothing waits on SHOP-47" and the captions. Add it to the cast in `00-README.md` as "SHOP-47 · Checkout
   address autocomplete · Backlog".

## Decisions needed (for the user, one at a time)
These come from the designer's open questions and this audit. Each one may touch an accepted decision.
- ~~**D1. Syntax colours in code blocks: licence.**~~ **Decided (0078):** keep the colours. highlight.js (BSD-3-Clause) is
  accepted as an exception to the MIT-only rule, used through `lowlight` and `@tiptap/extension-code-block-lowlight`.
- ~~**D2. ⌘K inside the editor.**~~ **Decided (0078, 0058 refined):** ⌘K / Ctrl+K means Link while the editor has focus,
  and Search / filter everywhere else, as drawn.
- ~~**D3. Nesting list items.**~~ **Decided (0078):** Tab / ⇧Tab indent and outdent inside lists, as in code blocks;
  elsewhere Tab leaves the editor. The focus annotation on sheet a/b needs this change (designer follow-up).
- ~~**D4. Esc in layers.**~~ **Decided (0078):** Esc closes a popover or menu first, then leaves the editor, and only then
  discards the form, as drawn. There is no unsaved-changes confirmation today; the last step discards as it does now.
- ~~**D5. Max height.**~~ **Decided (0078):** 480 px in the ⌘N form, as drawn. In short windows the form body scrolls and the
  Save / Cancel footer stays pinned (designer follow-up: show the pinned footer once, at 1440×900).
- ~~**D6. Notice for dropped paste content.**~~ **Decided (0078):** the muted "1 image left out" line, as drawn.
- ~~**D7. Where "Copy as Markdown" goes.**~~ **Decided (0078):** "Copy as Markdown" and Expand sit at the right end of the
  "What and why" label row in every state, not next to Edit (designer follow-up: move them; this also settles finding 4).
- ~~**D8. Overflow order.**~~ **Decided (0078):** Strikethrough, Quote, Table and Horizontal rule move into "…" first, as
  drawn. Expand and the Markdown toggle never move.
- ~~**D9. The Markdown toggle.**~~ **Decided (0078):** remembered per user, as drawn.
- ~~**D10. Older frames.**~~ **Decided (0078):** every older frame that shows the description field switches to the new
  editor (the MD Toolbar and MD Content components). The rest of each frame stays as it is.

- ~~**D11. Full-window view**~~ (user request, not from the design). **Decided (0078):** an Expand button opens the
  description over the whole Otaq window: at the toolbar's right end in edit mode (with header, toolbar, Save and Collapse),
  and next to "Copy as Markdown" in read mode. Esc collapses it after closing any popover. No shortcut. To be designed
  (designer follow-up).
