# Design update R: environment variables and warm builds (2026-10-16)

Decision **0082** keeps a worktree per ticket and adds three things. A new worktree starts from a warm build (the last Done
ticket's gitignored files, cloned copy-on-write). A per-project switch turns this off. Per-project environment variables
are set in every agent session, Run and Shell. The design agent drew update R into the main pages.
Affected briefs: 15 (per-project settings) and 16 (the Cleanup view). Brief 14 (onboarding) doesn't change.

### Key choices
- **Environment variables** are one per-project row with a full-width list: NAME (mono, 240 px) = value (fills the rest)
  and ×, then **Add variable**. Empty shows a "No variables. Sessions get your normal environment." box. The hint
  (`CI = true`, "e.g. so tools never wait for input or start watch mode") is always visible, and one line under the list
  says "Changes apply to sessions, Runs and Shells started after this." It is an example only, and there
  are no built-in, read-only or computed rows. Settings save on their own (no Save button). Enter or blur saves, Esc reverts
  or drops a new empty row.
- **Validation:** a name is invalid only when it would break the start (empty, or containing `=` or a null character).
  An invalid or duplicate row is kept and marked red with the reason, and it isn't set until fixed. The other rows still apply (for a duplicate, the first row wins).
- **Removing a row** has no confirmation, since it is a setting and nothing on disk is deleted (like Env files).
- **Warm build switch:** it asks only when turning it off would delete something. With no warm build yet it turns off
  silently, and turning it on never asks. When unavailable, the switch is disabled and off, with the reason under it and in
  its tooltip. It is never hidden.
- **Cleanup:** warm builds are **their own section below the leftovers' action bar**. It has a different background, a
  flame icon and the note "Kept to speed up new tickets. It grows over time; clear it to reclaim disk."
  - It has no checkboxes, a Clear… button on each row, rows sorted largest first, and a total in the section header.
  - Warm builds aren't counted in "N items", aren't part of "Delete selected…", and never light the rail's Cleanup dot.
- **No warm builds: the section is hidden** (not folded into "Nothing to clean up"), so Cleanup looks exactly as before
  0082. When there are no leftovers but some warm builds, the empty state stays (shorter) with the section under it.
- **Clear… doesn't turn the switch off**: the next Done keeps a new warm build. The confirmation says so.

## Background only, don't build from these
- The older Settings frames (project fresh / configured / dark otaq) and the older Cleanup frames (3 items, 20 items,
  empty, delete confirmation, dark). They don't have the 0082 rows. The 0082 frames above were copied from them.
- Sample sizes, SHAs and ages (otaq 36.1 GB at `9c41e7b`, 3 d; shop-web 4.2 GB at `3e1f9a2`, 2 h; billing-api 1.3 GB at
  `b7d20c4`, 6 d) are illustrative.

Not designed, because 0082 doesn't include them: a list of folders to leave out of seeding, size limits or automatic resets,
CPU-sharing controls, `$OTAQ_CPUS`-style placeholders, and a "started from a warm build" message on cards or panels.

## Open questions (all decided in the audit below)
1. **Running sessions.** Variables can't reach a process that is already running. Proposed: they apply to sessions, Runs and
   Shells started or resumed after the change. Should the row say so?
2. **Which sessions.** Does "every agent session" include the validator (0063), Project agents (0068) and Project terminals
   (17)? Proposed: yes, since all of them run in the project.
3. **Duplicates on Windows.** Windows names are case-insensitive. Proposed: there, `NODE_OPTIONS` and `node_options` count as
   duplicates.
4. **Secrets.** Values are stored in Otaq's database and shown in full. Masking or keychain storage isn't in 0082 and isn't
   designed.
5. **Which disk decides "unavailable".** Proposed: the disk under Otaq's data folder, where warm builds and worktrees live.
   The first seed comes from the user's own checkout. If that checkout is on another disk it can't be cloned: should Otaq
   make a plain copy, or skip the seed?
6. **Folder name.** 0082 says only "the project's warm-build folder in the app's data directory". `~/.otaq/warm/<repo>`
   (next to `~/.otaq/wt/<repo>`) is a placeholder.
7. **Clear while seeding.** If a new worktree is being cloned from the warm build when the user clicks Clear, should Otaq
   wait or say "in use, try again"? Not designed.
8. **Freed size.** A copy-on-write clone shares disk blocks. While worktrees cloned from it still exist, Clear can free
   less than the size shown. Should the toast say "up to 36.1 GB"?
9. **Turning off with no warm build.** Assumed: no confirmation when there is nothing to delete, and turning it on never
   asks.

## Audit (2026-10-16)
Checked against 0082. The frames match it:
- Environment variables: empty by default, `NAME = value` rows, no built-in, read-only or computed rows, no placeholders;
  invalid and duplicate names are marked and not set.
- Warm build switch: on by default, not in onboarding; turning it off clears the warm build behind a confirmation (0018);
  unavailable where the disk can't clone, shown disabled with the reason (Windows NTFS, Linux ext4), never hidden.
- Cleanup: warm builds in their own section (not leftovers), size, commit, age, Clear… with a confirmation; hidden when
  there are none; Clear doesn't turn the switch off.
- Nothing outside 0082 was designed (no exclude list, size limits, CPU controls, placeholders or card message).

Fixes asked of the design agent (they don't change behaviour):
- The four confirmation dialogs ("Turn off and clear" light and dark, "Clear…" light and dark) still hold a hidden
  `~/.otaq/wt/shop-web/SHOP-14 · 412 MB (remove worktree)` line copied from the leftover confirmation. Delete it, so a
  developer reading the layers doesn't think turning the switch off or Clear removes a worktree.

Decided during the audit (0082 changelog):
- **The hint's example names no language or tool:** `CI = true`, "e.g. so tools never wait for input or start watch
  mode", replaces `CARGO_BUILD_JOBS = 3` in every frame (light and dark). Fix asked of the design agent.
- **Q1 Running sessions:** a change applies to sessions started or resumed, and Runs and Shells started, after it;
  running ones keep the old values. One line under the list: "Changes apply to sessions, Runs and Shells started after
  this." No restart offer. Fix asked of the design agent (add the line).
- **Q2 Which sessions:** everything Otaq starts in the project gets the variables: ticket agents, the validator (0063),
  Project agents (0068), the Project terminal (brief 17), the size check (0081), Run and Shell. The row's text "every
  agent session, Run and Shell" stays.
- **Q3 Duplicates: the warning stays, as drawn** (the second row is marked and not applied; the first one applies).
  The user first dropped it, then kept it.
  On Windows names are compared ignoring case (`node_options` duplicates `NODE_OPTIONS`); on macOS and Linux they aren't.
- **Invalid names: only what would break the start is marked:** an empty name, or one containing `=` or a null
  character. A space or a leading digit is allowed. The "invalid name" frames keep their red state, with an example that
  breaks the start (e.g. `MAX=JOBS`) and wording to match. Fix asked of the design agent.
- **Q4 Secrets: plain, as drawn.** Values are stored in Otaq's database and shown in full; no masking, no keychain.
  Secrets already live in plain env files copied into every worktree.
- **Q5 Which disk:** the disk under Otaq's data folder (where worktrees and warm builds live) decides whether the
  switch is available. A first seed from the user's checkout on another disk is skipped (no plain copy): those tickets
  build from nothing until the first Done keeps a warm build.
- **Q6 Folder name:** `<app-data>/warm/<repo-name>` (e.g. `~/.otaq/warm/shop-web`), next to `wt/`. The placeholder in
  the frames is now the real name.
- **Q7 Clear while a worktree is being seeded: wait, then clear.** The row shows "Clearing… (waiting for SHOP-21's
  copy)" until the copy ends, then goes as usual. The same applies to turning the switch off. Fix asked of the design
  agent (one extra state of the warm-build row).
- **Q8 Freed size: "up to".** Both confirmations (Clear… and turning the switch off) say "up to <size>" (button "Clear
  up to 36.1 GB") with one line: "Tickets copied from it share part of this space, so it may free less." The toasts
  give no number ("Cleared otaq's warm build"). The rows and the section total keep the full size. Fix asked of the
  design agent.
- **Q9 Toggle with no warm build:** as drawn. The switch asks only when turning it off would delete a warm build;
  turning it off with none, or turning it on, never asks.

All open questions of update R are decided. Before the tickets are written, the design agent applies the fixes above:
the hidden SHOP-14 line, the `CI = true` hint, the "applies to sessions started after this" line, the invalid-name
example (`MAX=JOBS`), the "Clearing… (waiting for …)" row state, and the "up to" wording.
