## 1. Crewboard never mixes its text with yours (0048)
- A **"1 message waiting · Deliver now"** chip on the card and in the terminal header strip. It appears when an automatic message
  is held because the user has unsent text in that terminal. Sample: **SHOP-19**, with a ticket-change note waiting (section 10).
- **Unsent-text prompt** when the user clicks Send back or answers from the inbox while the terminal has unsent text:
  "SHOP-23 has unsent text in its terminal" with **Keep it and cancel** / **Clear it and send**.

## 2. Service update banner (0022)
- Global banner after a rebuild: **"Service update ready · Restart now (3 agents working, 2 waiting)"**. Calm, not urgent.
- Variant **"Restart required"**: the app can't talk to the old service, so only the Restart button works.
- Restart confirmation: "3 working agents and 2 waiting ones will be interrupted. You can Resume all afterwards."
- After the restart, the recovery state from frame 16 (Interrupted tickets, Resume all).
- Add it to the banner stacking rules in frame 11.

## 3. Dependencies work like beads; no stacking in v0.1 (0049)
**This is the biggest change.** Read the rewritten brief 12 first.
- A ticket starts only when **every dependency is Done · Merged** (Closed never counts). It branches from its base branch.
- **SHOP-20 is now Queued**: "waits for SHOP-18, SHOP-19 to merge". The line updates as parents move ("SHOP-18 in Review",
  "SHOP-18 · PR #482 open"). SHOP-21 stays Queued: "waits for SHOP-20 to merge".
- **Redo frame "12 · Stack & dependencies"** as brief 12's six-step storyboard: planning a chain → the chain runs (SHOP-20 waits)
  → one parent merged → all parents merged (SHOP-20 starts) → PR variant (Mark merged, then start) → closed parent.
- Open PR always targets the ticket's base branch. **Mark merged**: Done, then any waiting children start (toast: "SHOP-20
  started · all dependencies merged").
- **Keep:** dependency badges, chain highlight on hover/selection, the Stack list, "conflicts with main", and **Send to agent
  to fix** on a Local merge conflict (0038).

**Remove from every frame (deferred with stacking):**
- the **Paused** status and every "Paused · parent SHOP-18 changed" card, panel state, terminal state and legend entry
- **Needs restack**, **Restacking…**, **Resolving restack conflict**, **Restack conflict**, and the restack inbox item
- the bottom-up "approve SHOP-18 first" / disabled-approve state
- "stacked on SHOP-18" (the panel base reads "on `main`")
- stacked PR targets (a child's PR targeting its parent's branch), PR **retargeting**, **"PR out of date · Push"**
- "children restacked" toasts (replace with "2 waiting tickets started")
- the paused and restack icons in Foundations / Iconography

## 4. Finished tickets answer questions (0030)
- Sample: **SHOP-40.2** (Wishlist button, working) asks **SHOP-40.1** (Wishlist API, Done · Merged): "Which endpoint returns the
  wishlist?". The SHOP-40.1 card in Done shows **"answering SHOP-40.2"** while Crewboard has resumed it, answer-only.
- Messages section (panel): the question and answer, with "answered by resuming SHOP-40.1's session".
- Project settings: a toggle, **"Let finished tickets answer questions"** (on by default). When it's off, the question goes to the
  inbox ("SHOP-40.2 asks SHOP-40.1: …"), as in frame 10 today.

## 6. No alerts while you're looking (0042)
- A two-step storyboard (frame 06) for SHOP-19:
  1. The user chats in its **focused** terminal. The agent ends its turn and the card **stays calm**: no orange, no inbox item,
     no notification, only a subtle "your turn" in the terminal header strip.
  2. The user closes the panel without replying. SHOP-19 **turns Idle (orange)**, jumps to the top of Dev and appears in the inbox.

## 7. Workflow skills, branch names and the push confirmation (0050)
- **Open PR confirmation dialog** for SHOP-18 (Checkout API):
  - branch `feature/SHOP-18-checkout-api` (editable, validated live: valid name, not already taken)
  - one editable field per commit message, e.g. `feat(checkout): add POST /checkout` and `test(checkout): cover declined cards`
  - PR title and description, and the target (`main`)
  - **Push & open PR** / **Cancel**
  - also show: "Open PR skill is preparing…", pushing, success (PR #482 and its link), and an invalid or taken branch name
- **Push to PR** variant: the branch name locked (lock icon), and only the new commits editable.
- **Uncommitted-files refusal** on Local merge, Open PR and Push to PR: "SHOP-19 has 2 uncommitted files", with **View** and **Send back**.
- Cards and panels show the **temporary branch `crewboard/SHOP-18`** until the first push, then the real name (History logs the rename).
- **Settings → Workflow skills** (global, and per project with "use global"): **Commit**, **Push**, **Open PR**, each a skill
  name (`/crewboard:commit`, `/crewboard:push`, `/crewboard:open-pr`, or the user's own such as `/my-pr`).

## 8. Base branch per ticket (0051)
- `shop-web`'s default base stays `main`.
- Ticket editor: **"Start from and merge into: [main ▾]"** (local and remote branches), locked after the ticket starts.
  Sample: **SHOP-31 "Hotfix: checkout crash"** on `release/2.3`.
- The panel header and the Local merge / Open PR dialogs show the ticket's base. The conflict flag names it ("conflicts with `release/2.3`").
- The Depends-on picker rejects a link across bases: "SHOP-31 merges into `release/2.3`, SHOP-20 into `main`. Linked tickets
  must use the same base branch."

## 11. "Planning terminal" becomes the **Project terminal** (0019)
- Rename it everywhere: the header button, the shortcut list, the onboarding hint, the "01 · Components" annotations and the frame
  title ("17 · Project terminal").
- It opens as a **plain shell prompt in the project folder** (`~/code/shop-web`), not a running Claude session. The empty state
  hint: "plan tickets, run commands, or start `claude`". Show plain shell use (`git log`, `pnpm test`), then the user starting
  `claude` and splitting a feature into tickets that appear in Backlog.

## 12. Usage limit: plan meter and detection (0020)
- Board header: a **plan meter**, "5h · 82% · week · 40%", with reset times on hover, amber near the limit. Hidden for API-key users.
- Usage banner variants: the session limit ("resets 3:45pm"), the weekly limit ("resets Mon 12:00am"), and an unknown reset time.
- Safety net in the inbox: an Idle item with **"This is the usage limit"**. After the click, the Idle items fold into the banner
  and the agents show "Waiting for limit reset".

## 13. Epics and base branches (0051)
- Epic SHOP-40 editor: a base-branch field (`main`), locked once a child has started.
- Epic child editor (SHOP-40.2): the base shown read-only, "From the epic: `main`".
- Move-to-epic dialog: "SHOP-51 will start from `main` instead of `release/2.3`" when the bases differ.
- An epic dependency across bases is rejected in the Depends-on picker, with the usual hint.

## 14. Working in background is not "needs you" (0042)
- New neutral card status **"Working in background"** (not orange, no inbox item, no notification). Sample: SHOP-19,
  "background: test run, 1 helper agent · 6 min". Variant: "wakes up at 4:10pm" (a scheduled wakeup).
- Add it to the card-variants pages and, in the Dev order, with the working cards.
- Terminal header strip for that ticket: "Waiting on its background work (2)", with the task list on hover.
- Needs you appears only for real requests, including a permission prompt raised inside a helper agent. Sample text:
  "Needs you · helper agent asks: Allow `pnpm test --update-snapshots`?".
